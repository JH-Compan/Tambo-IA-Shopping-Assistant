# **Objetivo de la Retrospectiva**

Analizar los resultados obtenidos durante el Sprint 2, identificar los aspectos positivos, los problemas encontrados y las lecciones aprendidas en la fase final del proyecto Tambo AI Shopping Assistant (Tambot), así como evaluar el cumplimiento general de los objetivos del sistema.

# **¿Qué salió bien?**

- Se completaron las funcionalidades principales del sistema Tambot.  
- Se implementó el sistema de recomendaciones personalizadas basado en el historial del usuario.  
- Se logró el control de stock en tiempo real integrado con Supabase.  
- Se desarrolló el registro de interacciones del chatbot para análisis de usuarios.  
- Se inició el desarrollo del dashboard administrativo para gestión del sistema.  
- Se mantuvo la integración estable entre el frontend, backend en Flask y Supabase.  
- Se mejoró la lógica de consultas a la base de datos.  
- Se logró consolidar el chatbot como interfaz principal del sistema.  
- El equipo logró cerrar el proyecto cumpliendo los objetivos generales planteados.  
- Se mantuvo la organización del trabajo mediante GitHub Issues y control de versiones.

# **¿Qué problemas encontramos?**

- El desarrollo del dashboard administrativo tomó más tiempo del esperado debido a la complejidad de la integración con Supabase.  
- Algunas funcionalidades del dashboard quedaron en estado parcial o en desarrollo.  
- Fue necesario realizar varias optimizaciones en las consultas del sistema de recomendaciones.  
- El control de stock requirió ajustes repetidos antes de estabilizar su funcionamiento.  
- Se presentaron retrasos en la realización de pruebas de rendimiento del sistema.  
- La estimación de tiempo para algunas historias de usuario no fue del todo precisa.  
- La integración de varios módulos generó complejidad en la depuración de errores.

# **¿Qué aprendimos?**

- Es importante dividir sistemas complejos (como el dashboard) en módulos más pequeños para facilitar su desarrollo.  
- La planificación inicial de consultas a la base de datos es clave para evitar retrabajos.  
- Las pruebas continuas durante el desarrollo ayudan a detectar errores más rápidamente.  
- Supabase es una herramienta potente, pero requiere un buen diseño de estructura de datos.  
- La integración constante entre frontend y backend reduce problemas en etapas finales.  
- Scrum permitió organizar mejor el trabajo y mejorar la entrega progresiva de funcionalidades.  
- La comunicación constante del equipo fue clave para resolver bloqueos técnicos.

# **¿Qué podemos mejorar?**

- Mejorar la estimación de tiempos en tareas complejas.  
- Incrementar la realización de pruebas desde etapas tempranas del desarrollo.  
- Optimizar la arquitectura del backend para mayor escalabilidad.  
- Completar módulos que quedaron parcialmente desarrollados, como el dashboard.  
- Mejorar la precisión y rendimiento del sistema de recomendaciones.  
- Fortalecer la seguridad del sistema (autenticación y control de acceso).  
- Reducir cambios tardíos en la estructura de la base de datos.

# **Acciones finales del Sprint 2**

- Integración final del sistema chatbot con Supabase.  
- Implementación funcional de recomendaciones personalizadas.  
- Validación de stock en tiempo real completamente operativa.  
- Registro de interacciones del usuario implementado.  
- Dashboard administrativo iniciado como módulo de gestión del sistema.  
- Consolidación de la documentación final del proyecto.  
- Preparación de la demostración final del sistema Tambot.  
- Cierre del desarrollo bajo metodología Scrum en dos sprints.

# **Conclusión**

El Sprint 2 permitió completar el desarrollo del sistema Tambot, incorporando funcionalidades avanzadas como recomendaciones personalizadas, control de stock en tiempo real y registro de interacciones de usuarios, además del inicio del dashboard administrativo.

A pesar de algunos problemas en la estimación de tiempos y la complejidad de integración de módulos, el equipo logró consolidar un sistema funcional y coherente.

Con esto se da por concluido el proyecto Tambo AI Shopping Assistant (Tambot), cumpliendo los objetivos planteados bajo la metodología Scrum en dos sprints de desarrollo.
