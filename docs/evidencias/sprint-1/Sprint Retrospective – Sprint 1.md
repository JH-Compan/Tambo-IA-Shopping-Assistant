# **Objetivo de la Retrospectiva**

Analizar los resultados obtenidos durante el Sprint 1, identificar los aspectos positivos, los problemas encontrados y las oportunidades de mejora para los siguientes sprints del proyecto.

# **¿Qué salió bien?**

- Se logró construir la primera versión funcional del chatbot.  
- Se desarrolló la interfaz conversacional para interactuar con los usuarios.  
- Se implementó la consulta de promociones y búsqueda de productos.  
- Se integró correctamente el frontend con el backend.  
- Se realizó la migración de la información hacia Supabase como base de datos principal.  
- El equipo mantuvo comunicación constante mediante reuniones Daily Scrum.  
- Se organizó y actualizó la documentación Scrum del proyecto.  
- Se utilizaron GitHub Issues para gestionar las tareas del Sprint.

# **¿Qué problemas encontramos?**

- Inicialmente se planteó utilizar archivos Excel como fuente principal de datos, pero posteriormente se decidió migrar a Supabase, lo que generó cambios en parte del trabajo realizado.  
- No se contaba con un diagrama entidad-relación definido desde el inicio del proyecto, lo que ocasionó varias modificaciones en las tablas y estructura de la base de datos.  
- Hubo dificultades para determinar qué campos eran necesarios dentro de la base de datos.  
- Algunos integrantes tuvieron problemas de permisos para acceder a Supabase y consultar información.  
- Durante la integración del sistema aparecieron inconvenientes para visualizar correctamente los resultados de las consultas.  
- Se presentaron conflictos durante algunos Pull Requests debido a cambios simultáneos en los archivos del proyecto.  
- La actualización manual de conflictos en Git requirió tiempo adicional del equipo.

# **¿Qué aprendimos?**

- La planificación temprana de la arquitectura y base de datos reduce retrabajos posteriores.  
- Supabase ofrece una mejor alternativa para el proyecto en comparación con el uso de archivos Excel.  
- Es importante definir desde el inicio los permisos y accesos necesarios para todos los integrantes.  
- GitHub facilita el seguimiento de tareas mediante Issues y control de versiones.  
- La documentación continua permite mantener una mejor organización del proyecto.  
- Las reuniones Daily Scrum ayudan a detectar problemas de forma temprana.

# **¿Qué podemos mejorar para el Sprint 2?**

- Definir con mayor detalle la estructura de la base de datos antes de iniciar el desarrollo.  
- Reducir los cambios de tecnologías o herramientas durante la ejecución del Sprint.  
- Realizar pruebas de integración de forma más frecuente.  
- Mejorar la coordinación durante la creación y revisión de Pull Requests.  
- Mantener la documentación actualizada durante todo el Sprint y no únicamente al finalizarlo.  
- Incrementar la comunicación entre los responsables de frontend, backend y base de datos.

# **Acciones para el Sprint 2**

- Implementar recomendaciones para clientes nuevos.  
- Preparar historial de compras simulado en Supabase.  
- Implementar validación de stock.  
- Implementar resumen final del pedido.  
- Registrar interacciones básicas del chatbot.  
- Completar la documentación y evidencias del proyecto.  
- Preparar la demostración final del sistema.

# **Conclusión**

El Sprint 1 permitió establecer una base sólida para el desarrollo de Tambot mediante la implementación de las funcionalidades iniciales del chatbot y la integración con Supabase. Aunque surgieron dificultades relacionadas con cambios tecnológicos, estructura de datos y control de versiones, el equipo logró cumplir los principales objetivos planteados para el Sprint. Las lecciones aprendidas servirán para optimizar la organización, comunicación y desarrollo durante el Sprint 2\.
